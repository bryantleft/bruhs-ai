# Native mobile companion

`bruhs-mobile/` is an Expo 58 / React Native iOS and Android companion. It renders native conversation and task views, uses device secure storage, and connects directly to the computer that runs Bruhs. The desktop and task server remain the execution authorities. No managed relay, cloud worker, cloud speech fallback, EAS build or hosted update service is configured.

## Local setup

The verified development environment uses Node 26.13.0, npm 11.20.0, Expo 58.0.25, React 19.3.0, React Native 0.88.1 and TypeScript 6.0.3. Exact dependencies are in `bruhs-mobile/package-lock.json`. Native speech uses `expo-speech-recognition` 58.0.1. `expo-system-ui` 58.0.7 supplies Android dark-mode configuration. A scoped minimatch override fixes the Expo fingerprint dependency's published advisory; npm audit reports zero vulnerabilities.

From `bruhs-mobile/`:

```sh
npm ci
BRUHS_MOBILE_VARIANT=development npm run ios
# Android Studio's installed SDK and bundled Java are detected locally:
BRUHS_MOBILE_VARIANT=development npm run android
```

These are [Expo's local compilation commands](https://docs.expo.dev/guides/local-app-development/). Xcode or Gradle generates and builds the native projects locally. Use a development build, because the speech module is not bundled in Expo Go. Native folders, dependencies, private keys and build output are ignored by Git. The development app uses `dev.bruhs.mobile.development`; production uses `dev.bruhs.mobile`.

Keep Xcode's normal simulator signing and entitlement packaging enabled. A simulator build needs its application identity in the simulator entitlement sections. Passing `CODE_SIGNING_ALLOWED=NO` omits those sections and makes Keychain operations fail with `errSecMissingEntitlement`. Attaching iOS Keychain entitlements directly to an ad-hoc macOS signature is also incorrect: macOS rejects that executable. Expo's normal `run:ios` workflow retains Xcode's simulator packaging.

The app reuses the existing Apple team with scoped automatic signing. [Local iOS signing](native-mobile-ios-signing.md) documents metadata checks, device builds and archives. The local Release archive for `dev.bruhs.mobile` built successfully using the already installed App Store Connect team API key, which avoids the stale saved Xcode login. Its Apple Development signature and provisioning profile match the expected team and app; one registered device is included. The known paired iPhone is currently unreachable. This device-signed archive and the existing macOS Developer ID/notarization setup serve their respective targets; App Store export is a separate release step.

[Local Android setup](../bruhs-mobile/ANDROID.md) detects the existing Android Studio SDK and bundled Java without changing shell profiles. The verified debug APK uses a development key. Android distribution still requires the developer's release keystore. No store submission or cloud build was performed.

## Connect a computer

**Desktop session:** On the computer, create a one-use offer in Bruhs Mobile access. In the native app, scan that QR code or paste its full `https://computer/#pair=…` link. Review the displayed origin and give the saved computer a name. The exchange consumes the one-use secret and saves the resulting scoped device token. Read access is the default on the desktop; prompt, approval and diff access are granted there. [Desktop listener setup and controls](mobile-access.md) describe the host side.

The app also accepts `bruhs://pair?url=<percent-encoded-pairing-link>`. A deep link still opens the origin review step. It does not automatically exchange credentials. Duplicate or ambiguous pairing parameters, embedded credentials and non-root addresses are rejected.

**Durable tasks:** Select Task host and enter its root HTTPS address plus an owner or guest token issued in Workbench → Tasks → Phone and guest access. This uses a separate API and separate saved credentials. Owner access exposes task creation, prompts, exact approval IDs, stopping tasks and children, side questions, verification, bringing answers back, and resume-at-reset controls. Guest access reads the host's redacted projection and submits proposals for owner review. [Workbench companion behavior](workbench-mobile-v2.md) documents this authority.

Use an address reachable from the phone over a trusted local/private network or VPN, with a certificate trusted by the device. A physical phone's loopback address points to that phone. Production connections require HTTPS. Development builds additionally permit literal loopback HTTP for the synthetic simulator fixture; they do not allow arbitrary LAN HTTP addresses. Certificate verification remains enabled.

## Behavior and privacy

- Phone navigation shows one pane; tablet widths show a conversation list beside the detail view. Views use safe areas, system text scaling and 46 pt minimum buttons. Notices, recovery controls and the composer can scroll. A persistent approval shortcut returns to the exact review; composing follows the end, while reading elsewhere stops transcript following. Changes are immediate without animation, including reduced-motion devices.
- Desktop threads include live snapshots, earlier-message paging, full-message paging and revision-bound diffs. Network loss retains the last received state while disabling mutations. Reconnect checks current access and receipts. Expiry or revocation clears the displayed transcript and that host's drafts, stops further reads and offers re-pairing. Withdrawing diff scope closes an already open diff.
- Tokens, unsent drafts and exact pending desktop commands use [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/). iOS uses unlocked, device-only accessibility. Android backups are disabled and SecureStore backup exclusions are configured. Atomic generation pointers commit bounded encrypted shards; each data shard is at most 1 KiB UTF-8, below the documented historical iOS value limit. Storage errors block persistence and command dispatch instead of falling back to plaintext. Draft writes coalesce with the existing 1 second refresh cadence and flush on host switch/background; an abrupt kill can lose the latest unflushed keystrokes.
- Keychain data can survive an iOS uninstall. Revoke desktop access in the app or on the computer. Forgetting a task connection only removes its local token; revoke that token on the task host. Browser previews deliberately keep all credentials in memory.
- Provider logins and private native credential forms remain on the computer. The app stores only the companion credentials issued for its selected authority. No tokens go in request URLs. `expo/fetch` sends no cookies and uses `redirect:error`, which is implemented by its native iOS and Android transports. All authenticated routes are restricted to the saved canonical origin and authority family.
- Dictation uses the [maintained native speech module](https://github.com/jamsch/expo-speech-recognition) with `requiresOnDeviceRecognition:true` and audio persistence disabled. It appends English (US) recognition to an editable draft and never sends it automatically. Unsupported devices or missing Android offline models keep dictation unavailable; there is no network recognition fallback. The module's types and iOS implementation confirm that microphone consent is sufficient for this on-device path; the separate Speech Recognizer permission is required for the network path. Permission/model awaits are guarded by a foreground/mount generation, so a late response after backgrounding, cancellation or unmount cannot start recording.

## Command safety

Desktop calls use `/api/mobile/{pair,session,threads,thread,message,diff,command,disconnect}`. Read snapshots refresh at the broker's 1 second foreground cadence with a single request in flight. Paged text remains pinned until explicitly reloaded. Backgrounding aborts reads. The 16 second transport deadline leaves the broker its 15 second native dispatch deadline.

Before a desktop mutation, the app securely saves the exact UUID, sequence and action. Approval actions include the displayed request ID, turn generation and review hash. A receipt must match the saved UUID and sequence before the command unlocks. Recovery checks the server's last receipt and next sequence. An explicit retry transmits the same payload; it never synthesizes a replacement command. Accepted prompts clear only an unchanged matching draft, so typing during delivery is preserved. Rejected and unconfirmed receipts show their actual outcome; unconfirmed commands are not replayed.

Durable task endpoints are `/api/tasks`, `/api/commands` and `/api/proposals`. That API has no client idempotency receipt. The app saves an uncertainty marker before a task POST, never retries it automatically, and retains the marker for network, malformed-success or 5xx responses. The user must review the host state before enabling another action. A valid 4xx rejection is distinct from an uncertain response. Task tokens can never be used by the desktop route adapter, and desktop tokens can never be sent to the task routes.

## Re-run synthetic checks

```sh
# Terminal 1, in bruhs-mobile:
node test/host-fixture.mjs
# Terminal 2:
BRUHS_MOBILE_VARIANT=development npx expo start --dev-client --web --localhost --port 18440
```

The fixture prints its synthetic pairing fragment and owner/guest tokens. Pair the development simulator with `http://127.0.0.1:18441/#pair=<printed-fragment-value>`. Its `/__fixture/state` route exposes only synthetic state and controls for offline, revocation, scopes and receipt interruption. `mode:"native-pending-once"` reserves one desktop command and returns 500; `mode:"task-malformed-once"` accepts one task command but returns invalid JSON. After checking the exact receipt or the manual review gate, verify the recorded request/dispatch counts. Close the owned preview and stop the fixture/Metro server afterward. Shut down and delete only simulators created for this acceptance run.
